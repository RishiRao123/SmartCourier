SmartCourier

An Enterprise Microservices Logistics Ecosystem

Capgemini Technical Viva Presentation

Problem vs. Solution

The Problem: Fragmented Logistics

  • Manual tracking updates causing delays
  • Siloed data between delivery and billing
  • Monolithic architectures failing under load
  • Insecure communication and poor observability

The Solution: SmartCourier

  • Centralized, automated courier tracking
  • Decoupled microservices architecture
  • Real-time event-driven notifications
  • Secure JWT/OTP auth & distributed tracing

High-Level Design (HLD)

A robust, scalable microservices architecture enabling independent deployment and scaling.

  • API Gateway: Single entry point, routing, and edge security.
  • Eureka: Dynamic service discovery and registry.
  • Config Server: Centralized external configuration management.
  • Independent Services: Auth, Delivery, Tracking, Admin, and Notification.

Backend Technology Stack

Spring Boot 3.x

Provides the foundation for our RESTful APIs, leveraging autoconfiguration and embedded Tomcat for rapid deployment of each microservice.

Spring Data JPA & Hibernate

ORM layer handling complex database interactions, relationships, and schema generation with ease.

MySQL 8.0

Relational databases separated per microservice (Database-per-service pattern) to ensure loose coupling.

Maven & Docker

Robust dependency management and containerization for consistent environments from dev to prod.

Authentication Flow: JWT + OTP

  • Step 1: User authenticates with credentials.
  • Step 2: Auth Service generates 6-digit OTP via RabbitMQ to Email.
  • Step 3: User submits OTP for verification.
  • Step 4: Secure JWT (RS256) is issued containing role & claims.
  • Step 5: API Gateway validates JWT on all subsequent requests.

Asynchronous Event-Driven Logic

Decoupling core business logic from auxiliary tasks using RabbitMQ.

  • Producers: Delivery Service emits events (Booking, StatusUpdate, Delivered).
  • Message Broker: RabbitMQ handles routing and guarantees delivery.
  • Consumers: Notification Service listens and triggers emails.
  • Benefits: Zero blocking on main delivery flow, high availability, and easy retry mechanisms.

Database Entity Relationships

Enforcing data integrity across distributed databases.

  • User Entity: Centralized auth and profile management.
  • Delivery Entity: Core domain model with embedded Sender/Receiver properties.
  • Invoice Entity: 1:1 mapping with Delivery for billing.
  • Tracking Event: Append-only event store linked via unique Tracking Numbers.

Observability & Tracing

Tracking requests across distributed microservices is critical for debugging and SLA monitoring.

Micrometer & Zipkin

  • Trace ID: A unique identifier applied to a request as it enters the API Gateway.
  • Span ID: Identifies specific work units within individual microservices.

Logging Strategy

Logs are aggregated with context. Example payload:

[auth-service, TraceId: 8a4b2c, SpanId: 1f9d4e]
INFO: Authenticating user 'admin@smartcourier.com'

Frontend Architecture: React

A modern, modular approach using a Monorepo structure for Admin and User portals.

Custom Hook Pattern

Abstracting complex state and API logic out of UI components.

  • useDashboard(): Fetches aggregated stats.
  • useTracking(): Manages real-time tracking polling.

UI/UX Strategy

  • Vite for lightning-fast HMR and builds.
  • Tailwind CSS for utility-first styling.
  • Context API for global state management (Auth).

Refactoring Impact: Clean Code

Before (Bloated Components)

  • API calls mixed with UI rendering
  • Duplicate error handling logic
  • Hard to mock during unit testing
  • Massive files (500+ lines)

After (Separation of Concerns)

  • API logic moved to dedicated service files
  • State management delegated to Custom Hooks
  • Components focused strictly on presentation
  • High testability & maintainability

Future Enhancements for Scalability

Roadmap for evolving SmartCourier into a highly-available, production-grade system.

  • Redis Caching: Implement caching for frequently accessed data (e.g., User Profiles, Static Configurations) to reduce DB load.
  • CI/CD Pipelines: Automate testing and deployment using GitHub Actions or Jenkins.
  • Kubernetes Deployment: Move from Docker Compose to K8s for auto-scaling, self-healing, and zero-downtime rolling updates.
  • Elasticsearch: Advanced full-text search capabilities for historical tracking events and admin logs.
